# Plan 001: Extract the desktop input lock into a gem

Status: reviewed by every project's session (rove-2d-09 for Lota,
tokra-02, deckbuilder-1c, fledge-d2). The macOS core and the command are
built; Linux speech and Windows locking come next. Licence decided:
AGPL-3.0-or-later, keeping the licences of any configuration or snippets
adopted from elsewhere.

## Why

Lota (`rove_2d/tasks/desktop_input.rb`), Tokra
(`tokra/test/integration/support/keyboard_notice.rb`) and Deckbuilder
(`deckbuilder/gui/conf.rb`) each carry their own copy of one protocol: an
exclusive `flock` on `/tmp/desktop-input.lock`, a marker at
`/tmp/desktop-input.away`, a 3-second settle, and two fixed sentences. The
copies have already drifted (below), and each fix has to be made three
times. Fledge is about to need it too. A gem keeps one copy and the
protocol, its files, timings and words unchanged.

## Name

`desktop_input_lock`, constant `DesktopInputLock`, in
github.com/setdef/DesktopInputLock: the maintainer's choice, descriptive,
no trademark, and free on RubyGems. Lota and Deckbuilder rename
`DesktopInputLock` as they migrate; the protocol's file names
(`/tmp/desktop-input.lock`, `/tmp/desktop-input.away`) and
`DESKTOP_INPUT_QUIET` keep theirs, since other projects already use them. Pure Ruby, no runtime dependencies (stdlib
`monitor`, `rbconfig`), Ruby >= 3.4.

## API

Lota's interface under the new name, so Lota's migration is a rename:

```ruby
require "desktop_input_lock"

DesktopInputLock.hold { menu.popup(window) }       # speaking span; returns the block's value
DesktopInputLock.hold(speak: false) { move_pointer } # silent span
lock = DesktopInputLock.acquire(speak: false)      # setup ...
lock.release                                   # ... teardown

input = DesktopInputLock.new(lock:, marker:, say:, osascript:, settle:, env:,
  host_os:, log:, tell_limit:)                 # for tests: own files, fake say
input.speaks? / input.call_back / input.tick / input.finish
DesktopInputLock::LOCK, MARKER, SETTLE, STEP_AWAY, COME_BACK, WAITING, TELL_LIMIT
```

No shared mode. Lota's reliability work considered letting windows that
never take focus hold the lock shared, and chose not to: other lanes'
windows proved harmless. So the gem has no `shared:` keyword and the
command has no `--shared` (see Decisions). If one is added
later, `flock` can't turn a shared lock into an exclusive one atomically,
so a process would keep one descriptor and a counted mode, nest
exclusive outside and shared inside, and raise rather than deadlock when
a process holding the lock only shared asks for it exclusive.

### One session's own lock

Lota is adding a hidden macOS test session: a second user, logged in in
the background, whose windows, focus and pointer are its own. Its tests
can't disturb the person's session, yet a machine-wide lock makes the two
wait on each other. So `DESKTOP_INPUT_LOCK`, when set, names the lock
file, and the marker is the same path with its `.lock` extension
replaced by `.away` (or with `.away` appended if it has none). `DEFAULT`
and the `desktop_input_lock` command read it once, as they start. Unset,
the files are `LOCK` and `MARKER`, as the protocol agrees, and those
constants never change. The README says to point a session at its own
files only when nothing outside that session can take the same focus or
pointer, and only at a path every process of the session can reach.

The lock is taken on macOS and Linux, CI included. An uncontended
`flock` costs nothing, and Lota needs it on CI for its parallel lanes. A
project that wants Tokra's narrower scope keeps a one-line guard in its
own wrapper, rather than the gem growing an option. Speaking happens only
on macOS, outside CI, without `DESKTOP_INPUT_QUIET`.

On Windows (0.2.0) it locks in `%ProgramData%`; before that it locked nothing unless given paths. No
lane takes the lock there today, `/tmp` would mean a `C:\tmp` that may not
exist, and `Dir.tmpdir` would break the agreement on a shared path.

Linux locks (confirmed by rove-2d-09): each of Lota's Linux gate lanes
has its own Xvfb display, so the lock is uncontended there, but a person
can run a gate on one Linux desktop, and an uncontended `flock` is free.
`speaks?` is false on Linux and Windows whatever the environment.

### The command, for shell scripts

Fledge's delivery scripts are bash, and macOS has no `flock(1)`, so the
gem ships an executable (asked for by fledge-d2):

```sh
desktop_input_lock hold [--speak] -- CMD ARGS...
```

It takes the lock, runs CMD as a child, exits with CMD's status (128 + n
for a signal), and lets go. It forwards INT, TERM and HUP to CMD and
lets go once CMD ends. If the command itself is killed, the system frees
the lock. The command is silent by default, unlike `hold`, because a
shell script usually runs unattended. `--speak` makes it a speaking span
that calls the person back before it exits. It is a thin shell over
`DesktopInputLock#hold` and is tested by running it as a real process.

### Linux and Windows, after the core

The maintainer would like the gem to work fully on Linux, and on Windows
if it can. Both came after every project had migrated, in 0.2.0. The
protocol on macOS stays exactly as it is.

- **Linux** already locks. On a desktop session (`DISPLAY` or
  `WAYLAND_DISPLAY` set, `CI` unset, not quieted) a speaking span would
  also speak: the banner through `notify-send`, which takes no focus, and
  the voice through `spd-say` or `espeak-ng`, each skipped where it's
  missing, as on macOS. A Linux process speaks with the same marker,
  settle and words, so it interoperates with every other copy.
- **Windows** would lock a path that every user's processes agree on.
  `/tmp` doesn't exist there and `%TEMP%` differs per user, so they are
  `%ProgramData%\desktop-input.lock` and `.away` (see Decisions). The banner and voice would go through PowerShell
  (a toast through `Windows.UI.Notifications`, the voice through
  `System.Speech`), which need no install. The words reach PowerShell through its environment, never
  inside the script it runs. How it speaks is tested on every system,
  with stand-ins and `host_os:` naming Windows. A real Windows (CI)
  also checks the paths, a lock two processes contend for, and that both
  scripts parse. The tests that need a POSIX shell or `SIGSTOP` skip
  there.

### Decisions

- **Releases** (the maintainer, 2026-11-02): before 1.0.0, orchestration
  and solo agents tag and publish GitHub Releases, `0.0.X.pre.Y` until
  the gem is ready for other libraries to try and `0.X.Y` after. Only a
  person publishes to RubyGems.org. The first release is 0.1.0: all four
  projects reviewed the design, Lota depends on it with its gate green,
  and CI passes on macOS, Linux, and Windows.
- **Windows paths:** `%ProgramData%\desktop-input.lock` and
  `%ProgramData%\desktop-input.away`, directly in the folder. ProgramData
  is Windows' standard folder for data that every user shares, and every
  user may create files in it. A folder of the gem's own inside it would
  belong to whoever made it first, so other users could not create files
  there. Another user can open a file there but not rewrite it, which is
  the same edge the marker already has in `/tmp`.
- **A session's own lock** stays `DESKTOP_INPUT_LOCK`, its marker derived
  beside it. It is the protocol's prefix plus the one thing it names, and
  Lota's hidden session already uses it.
- **No shared mode** until a project shows a test that needs one. Lota
  found other lanes' windows harmless, and every copy of the protocol
  takes the lock exclusive.

## Where Lota and Tokra differ

| # | Behavior | Lota | Tokra | Gem |
|---|---|---|---|---|
| 1 | Watcher stopped on exit | between ticks only (251e452) | `Thread#kill` at any time, so it can cut off "come back" after the banner | Lota's. **Tokra has the bug.** |
| 2 | Hung `osascript` or `say` | killed after `TELL_LIMIT` 30 s (4a3ce54) | waits forever, so the exit hangs | Lota's. **Tokra has the bug.** |
| 3 | A Mac with neither `osascript` nor `say` | writes the marker and says nothing, so other processes stay silent too | silent span, no marker, as Plan 046 says | Tokra's. **Lota has the bug.** |
| 4 | `osascript` output | inherited; its errors show up in test output | discarded (`say` inherits, and prints nothing) | Tokra's |
| 5 | Where it locks | everywhere, even when quiet | macOS outside CI, even when quiet | macOS and Linux, even when quiet (see API) |
| 6 | Quiet variables | `DESKTOP_INPUT_QUIET` | also `TOKRA_QUIET` | gem: `DESKTOP_INPUT_QUIET`; Tokra's wrapper maps `TOKRA_QUIET` |
| 7 | Surface | `hold`/`acquire`/`release`, `speaks?`, `call_back`, `tick`, `finish`; inject paths, `say`, `osascript`, settle, env, host OS, log, tell limit | `taking_the_keyboard`, block optional; `Desk#call_back`, `#finish`, `#stop`, `#tick`; inject paths, settle, voice, banner, err, clock, sleep, watcher (no env or host OS) | Lota's |
| 8 | Nested and threaded spans | one descriptor per process, counted | the same | the same |
| 9 | Tests | real processes, fake `say` script | mostly a fake clock and recorder lambdas | Lota's, plus Tokra's cases it lacks (below) |

Both have the same two known edges, which the shared-protocol header
already records: a retrying watcher can call the person back in the gap
between another process's spans, and a marker in sticky `/tmp` can't be
deleted by another user. Closing either changes the protocol, so the gem
documents them and leaves them open. Fixing them would be a protocol v2
that every project agrees to.

Deckbuilder diverges as well. It holds the lock for the whole run, opens
it `RDWR`, and prints its own waiting line instead of `WAITING`.

## Tests

Real processes, a real `flock`, and `say` and `osascript` replaced by
scripts that record what they were given, as Lota's are. No mocking the
lock, no retries, no sleeps used to cover races: processes hand over
through files and `SIGSTOP`/`SIGCONT`, as Lota's do. Lota's 20 tests come
across first. To them I add the Tokra cases they lack, each run against
real processes, and each new test must fail first: a Mac without either
command stays silent (#3), `osascript` output is discarded (#4), a marker
from a process we may not signal (`EPERM`) counts as live, the watcher
stops once the marker is gone, an exit after settling calls back without
waiting, and `hold` returns the block's value. No test moves or blocks
the person's mouse, and none speaks for real.

## Repository

The skeleton comes from the most recently set-up repos (fledge, then
Ferro and rove_2d), as each stood at its earliest commits rather than as
it stands now, so it carries the setup without later project-specific
additions. The three already differ in most files, among them `.rubocop.yml`,
`mise.toml`, `tasks/lint.rake`, `tasks/package.rake` and the documentation
style. Where they conflict, I keep what they have in common and generalize
what is specific to one project (LÖVE parity, Rust and Cargo, Tauri)
rather than copying any one of them: `AGENTS.md`, `Steepfile` with `sig/`
and no `untyped`, `REUSE.toml` and SPDX headers inside `#--`/`#++`,
`mise.toml`, `.pre-commit-config.yaml`, `tasks/*.rake` loaded from the
`Rakefile`, RDoc in the documentation style, a README for Rubyists, a
CHANGELOG, and a `rake` gate of tests, RuboCop, Steep, RDoc coverage and
REUSE.

## Migration, per project

Status of each migration:

- Lota: done in Lota 9a700d6, pinned to aa02056 (the same `lib/` as
  `v0.1.0`), with its full gate
  passing. Its copy and that copy's test are deleted, and its reference
  cache no longer keys on the lock.
- Tokra: done in Tokra b80c9a7, pinned to 2bb238b (the same `lib/` as
  `v0.1.0`), with CI green on all three systems. `KeyboardNotice` is a thin
  wrapper, and `Desk` and its fake-clock tests are gone. It moves to the
  tag in a follow-up.
- Deckbuilder: done, pinned to `v0.1.0`. `gui/conf.rb` acquires a silent
  span inside its unattended-runs guard, and its inline copy is gone.
- Fledge: done in Fledge 9efbbe0, pinned to `v0.1.0` in its development
  group. Its AGENTS.md puts local runs that take focus under
  `bundle exec desktop_input_lock hold -- COMMAND`. No CI use.

Before the gem is released, each project points at it by `path:` or
`git:` (github.com/setdef/DesktopInputLock).

- **Lota (rove-2d-09).** Add `desktop_input_lock` as a development
  dependency and rename `DesktopInput` to `DesktopInputLock`. Swap
  `require_relative` for `require "desktop_input_lock"` in about nine
  files: `tasks/package_check.rb`, `tasks/gate.rake` (a comment),
  `test/native/{cursor,error_handler,restart_run}_test.rb`,
  `test/native/focus_for_tests.rb`, `test/parity/parity_helper.rb`,
  `test/parity/run_test.rb`, and `test/lovetest/tests/window.rb` (a
  comment). Then delete `tasks/desktop_input.rb` and
  `test/tasks/desktop_input_test.rb`, which the gem's tests replace.
  Two need more than a swap. `run_test.rb` spawns a child with `ruby -r
  .../tasks/desktop_input`, which becomes `-rdesktop_input_lock` under
  Bundler's environment. `reference_cache.rb` keys cached reference runs
  on the lock's source, and Lota decides what replaces that. Behavior
  changes only by #3 and #4.
- **Tokra (tokra-02, approved).** Add the development dependency and
  keep `KeyboardNotice` as a thin wrapper of a few lines:
  `taking_the_keyboard(speak:)` calls `DesktopInputLock.hold(speak: speak
  && !ENV["TOKRA_QUIET"])` behind its `locks?` guard (macOS outside CI).
  On Linux CI each job runs in its own container, so `/tmp` there is
  private and a lock guards nothing. `locks?`, and `speaks?` if kept,
  stay public module methods, which the surviving wrapper tests stub.
  Tokra's two callers (`context_menu_test.rb`, `tray_menu_test.rb`)
  always pass a block, so the block-optional form can go. Delete `Desk`
  and its fake-clock tests, and update Plan 046 and AGENTS.md. This fixes
  #1 and #2.
- **Deckbuilder (deckbuilder-1c).** `gui/conf.rb` can't require a gem
  yet: `bin/gui` runs Lota without Bundler. It will gain `bundler/setup`
  soon for another gem. Then `conf.rb` becomes `DESKTOP_INPUT =
  DesktopInputLock.acquire(speak: false)`, kept for the run, with its
  own guard (unattended runs only, `SNAPSHOTS` or `QUIT_AFTER`) left in
  `conf.rb`. Until then the inline copy stays, prints the protocol's
  `WAITING` line, and points at the gem. Deckbuilder never releases: the
  process's exit frees the `flock`. The RDoc for `acquire` says that the
  process's `DEFAULT` instance holds the open lock, so garbage collection
  never closes it, whether or not the caller keeps the returned object.
- **Fledge (fledge-d2).** It doesn't use the lock yet. Add the gem to
  the development group, pinned by version and checksum, and wrap the
  local rake tasks that drive the iOS Simulator or a macOS app
  (`tasks/mobile_parity.rb` and similar) in `DesktopInputLock.hold(speak:
  false)`. Wrap its bash delivery scripts in `desktop_input_lock hold --`. No CI
  use. It needs a git tag or a released version; tagging and releasing
  are the maintainer's call.

Each project's session makes its own change. I send each one a short
migration note and edit no other repository.
